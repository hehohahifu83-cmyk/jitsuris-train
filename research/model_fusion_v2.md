# マルチビュー融合 v2：表グラフ・学習ゲート・重大リスク拒否

v1 の固定確率平均を、入力ごとに専門家の使い分けを学ぶ融合器へ拡張する。実装は [model_fusion_v2.py](model_fusion_v2.py)。v1 は単純平均の比較基準として残す。

## v2 で増やしたもの

1. **非線形スタッカー**  
   E5、疎な特徴モデル、任意の追加専門家の確率・確信度・上位差・モデル間一致を入力し、HistGradientBoosting が列ごとに統合方法を学ぶ。ひとつの固定比率で全列を処理しない。

2. **同じ表の列をつなぐ軽量グラフ特徴**  
   各列をノード、同じ表の列を近傍として扱い、対象列自身を除いた近傍予測の平均分布・1位分布を集約する。列名や正解ラベルを隣列からコピーせず、他列の予測だけを伝える。GAIT の「表内依存をグラフで扱う」発想を、小さく既存モデルに接続できる形にした。これは論文のGNN実装そのものではない。

3. **重大誤りの別ゲート**  
   表単位の交差分割でスタッカーの予測を作り、重大ラベルを含む誤りを別のリスク判定器に学ばせる。重大誤りが8件未満ならリスク学習をせず、確信度と専門家の不一致による保守的な基準へ切り替える。

4. **較正条件を満たさなければ失敗扱い**  
   学習用OOF予測と、別表で作った較正用予測を分ける。較正では「重大誤り0、断定した全体の誤り5%以下、不明10%以下」を同時に満たすしきい値だけを採用する。条件を満たせない場合は、より緩いしきい値に勝手に変えず、学習をエラー終了する。

## 使う入力

- 必須：encoder と sparse の各列確率。
- 任意：15分類の確率を出す追加モデル。numeric_specialist は15分類または数値5分類の行列に対応。
- 全列の表ID。行順は確率行列と一致させる。
- 正解ラベルは学習用OOF部分と独立した較正部分だけに渡す。

値だけの検査器は予測へ投票させず、既存の verifier / guard / recheck の拒否役を維持する。v2 の判定後に既存ルールを通した製品全体の不明率・重大誤り率も、別途測る必要がある。

## データ分割の必須条件

- 学習用の各行のベースモデル確率は、その表全体を学習から外して作ったOOF予測であること。
- 較正用の表IDは学習用と重複しないこと。実装はこの重複を検査する。
- 実装のフラグ base_predictions_are_oof と calibration_is_held_out は呼び出し側の申告であり、元モデルが本当にその分割で学習されたかまでは検証できない。
- 固定済み評価セット・封印セットの予測や正解を、重み・しきい値の選択に使わないこと。

## 現在の位置づけと限界

これは v1 より表文脈と入力別ルーティングを強くした学習可能な候補だが、**まだ学習も性能比較もしていない**。しきい値の条件も有限の較正表で観測した値であり、未知データで重大誤りゼロを保証しない。表の分布が変われば成績も変わる。

HistGradientBoosting を使うため、現状は研究用のPython推論器である。ジツリスのブラウザー版へ入れるには、学習済み木とリスク判定器をJavaScriptで同じ順に実装し、Python/JavaScript一致とモデルサイズを測る必要がある。単一のモデル重みだけ差し替える形ではない。
