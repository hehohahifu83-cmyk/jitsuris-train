## 境界で要修正

1. **値が同じでも末尾0で判定が変わる**。合成値 `0.120000001` はprecisionで止まるが、`0.1200000010` は通る。Decimalとして同じ数だが、10桁以上という文字数条件にだけ差がある。さらに `0.0000000001` という正確な非ゼロの小数も金額として通す。絶対差1e-8以下は上限として有効でも、それだけで二進浮動小数の表現誤差とは言えない。10桁以上の文字数を誤差の根拠にしない。
   - 数値として同一の表記の不変性、ULP等の表現誤差との整合性と厳しい絶対上限の両方、真の小数が混在した場合を先に定義して検査する案を推奨する。閾値をこの反例にだけ合わせ込まない。
2. **大きい値で新しい例外**。`123456789012345678901234567890.0000000001` は旧check_assertではunknown/amount_precisionだが、NではDecimal.quantizeでInvalidOperationとなる。tryがDecimal生成だけを囲みquantizeを囲まないため。「新しく止めることはない」以前に、採点/利用の全処理を落とし得る。表現の範囲外・演算例外は元の停止を維持すること。
3. 厳密な英語式の桁区切り、真の3桁以上の小数や混合列の停止、他のcue/期間の停止、文脈終了後の関数復元はprobeで確認できた。上の問題を直す際も維持すること。

boundary_probe.py/result.jsonは16の合成入力と、混合列・他の停止・関数復元の確認。既存test_recheck*.pyは8件成功。候補や製品に修正を適用していない。
