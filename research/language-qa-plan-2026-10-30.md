# 最低限の言語能力：利用者と質疑応答ができる（2026-10-30 Claude）

オーナー指示（2026-10-30）：
> 「道具はジツリス本体が能力の限界と思われる域まで達し、最低限の言語能力を身につけさせたあとだ」
> 「最低限の言語能力とは利用者と質疑応答が可能なレベルという意味だ」

直前の会話で Claude は「最低限の言語能力」を「列名の意味が分かる力」と読み違えた。正しくは、**利用者が質問し、ジツリスが言葉で答えられること**。2026-10-25 の「言語能力の専門家」（`research/experts-plan-2026-10-25.md` の 4・E、2026-10-26 から保留）がこれに当たるので、保留を解いて順番に入れる。

## 順番
1. 本体を限界まで伸ばす（教材の付け直し → 入力をそろえる → 学習し直し、伸びが種子のぶれに収まって止まるまで）
2. 最低限の言語能力（質疑応答）を身につけさせる ← この文書
3. そのあとで専用の道具（値の書き方の検査・検査数字・日付・辞書など）

列名の意味の試験（直前の会話の案 3）は、本体の伸びを見る試験として 1 の中に残す。言語能力の合格の線にはしない。

## 「質疑応答が可能」の中身（合格の線の案）
- 日本語で質問を受けて、日本語で答える（英語は次）。
- 答えられる質問：
  - 判定について：「この列はなぜ金額か」「不明の列はどれで、なぜ不明か」「日付の列はどれか」
  - 種類について：「account と org の違いは」（LABEL_GUIDE の範囲）
  - 使い方について：「どの形のファイルが読めるか」「データは外に送られるか」
- 根拠は、ジツリスの判定の結果・列の値・LABEL_GUIDE だけ。根拠がなければ「分からない」と答える。作り話をしない。
- 判定と確信度は変えない（判定は本体・検査役・決め方の段が決める）。
- ブラウザの中だけで動き、表を外に送らない。

## 部品
- 最初の候補：Qwen3-0.6B（Apache 2.0）を素のまま（2026-10-25 の決定 E）。ブラウザで 4 ビットにして約 0.4〜0.5GB、WebGPU で動かす。
- 素で線に届かなければ、少ない教材（質問と答えの組）で LoRA の学習をする。学習は Kaggle の GPU なので、事前記録を書いたうえでオーナーの許可を取る。
- 読み込めない端末（WebGPU がない・メモリが足りない）用に、定型の説明を用意する。

## 試験（質疑応答の試験）
- 質問と正しい答えの要点の組を作る：判定・種類・使い方の 3 分野、合わせて 200 問ほど。根拠のない質問（答えは「分からない」）も 2 割入れる。
- 表は確かめる陣から取り、本体の学習に使った陣とは分ける。
- 採点：要点が合っている・根拠の外のことを言わない・日本語として通じる、の 3 つ。作るのと採点は ChatGPT と Claude が別々に行い、食い違いを Claude が裁定する。
- 実機（iPhone の Safari を含む）で、初回のダウンロード量・メモリ・最初の答えまでの時間を測る。

## いま決まっていないこと
- 合格の割合の線（例：要点が合う 80% 以上・作り話 2% 以下）。オーナーと決める。
- 本体の伸びが止まる前に、質疑応答の試験だけ先に作ってよいか（学習はしないので、本体の作業と並べて進められる）。
