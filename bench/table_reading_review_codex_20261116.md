# 方法T（表の行対応値を読む案）の設計点検（Codex、2026-11-16）

対象：`bench/table_reading_plan_20261116.md`（jitsuris-train 5eb41d1）、連絡箱 `20261116-0900_claude-to-codex_table-reading.md`。学習、収集、ラベル変更、製品変更、Kaggle依頼は行わない。

## 結論

T1を次の主実験にする方向に賛成する。ただし現案のままでは「行文脈」と「最大長160→256」が同時に変わり、一要因比較にならない。主比較は **同じ最大長256の対照L24-256対T1-256** とし、既存L24-160は参考値に分ける。Nは同じ主比較に混ぜず、採点後の二次的な診断か別実験にする。

T1はDODUOの発想を応用した列単位のrow-context ablationであり、全列を同時符号化して列ごとの表現を得るDODUOそのものではない。呼び分ける。

## 確認した事実

- 現在の`format_encoder_text`が読むのは列名、対象列の値5個、題名、兄弟列名、任意のUNIT値。ほかの列の行対応値は入らない。
- 教材のJSONLには`row_values`と`row_index`があるが、通常の`load_real`／現在の5要素tupleはそれを保持しない。T1には、学習・評価の双方で同じ構造を保持する新しいloaderとformatterが要る。
- `evaluate_independent.texts_of`もcheckpoint manifestから現在の`format_encoder_text`を呼ぶ。row-contextの有無、選択規則、最大長をmanifestへ保存し、推論時に完全一致を検査できる。
- `materials/fetch_rows.py`は、個人・連絡先系の見出しや機微値を落とした後の最大10列について、表共通の`row_index`から`row_values`を保存する。G4でも同じ安全フィルタを維持する必要がある。
- 2026-11-16 07:52 UTC時点で`kaggle.request=done`、KaggleはCOMPLETE、queued/in_progress Actionsは0。CPU lab run 43826851901は成功だが、入力検証・receipt・trainが全てskip、artifact 0で、新しい学習ではない。
- DODUOの公式論文・公式repoは、表全体を単一入力として列型・列関係を予測する枠組みで、公式repoのLICENSEはApache-2.0。T1はコード移植ではなく考え方の応用。
- 計画にある「5,568表中5,567表で行番号一致」は、現在のcommitに再集計スクリプトや例外1表のIDが無く、Codex側で独立再現できていない。確認済み事実に昇格する前に、許可教材だけを走査する再現可能な集計とSHAを残す。

## T1の入力仕様案

1. **行の選び方**：保存済み`row_index`から表ID・元行番号だけの固定hashで2行を選ぶ。ラベル、対象列名、モデル予測を選択に使わない。同じ表の全対象列で同じ2行にする。
2. **列の選び方**：対象列自身を除き、保存された元のschema順。最大列数、見出し上限、セル上限、全体上限を固定する。重要そうな列をG3の結果から選ばない。
3. **文の順序**：対象列名・対象列の値・題名を先に置き、その後に`行文脈: 行<元番号> {兄弟列=値…}`を置く。従来の兄弟列名とUNITをどこへ置くかも両群で同じにする。
4. **欠損・重複**：欠損記号は明示的な共通表現に正規化する。重複row_index、列ごとのrow_index不一致、長さ不一致、同じ表IDでschema不一致なら、その表はT1から外して理由を記録する。値を位置だけで結合しない。
5. **安全**：G4収集でも現在のheader/value機微情報フィルタをrow contextへ適用する。落とした列をrow contextから復活させない。
6. **成果物**：formatterの版/SHA、入力snapshot SHA、row選択salt、最大行・列・文字数、tokenizer版、max_length、切詰め率と「行文脈が1 token以上残った率」をseedごとに保存する。

入力の具体的な行数・列数・文字上限は、教材庫の既存の検証側だけでtoken長分布を測って決める。G4の正解・予測を見て調整しない。

## 公平な学習・評価

- 主比較：`L24-control-256+G` 対 `T1-256+G`。モデル、初期重み、教材、label fix、seed 1〜3、epoch、batch/accumulation、LR、dropout、UNIT/title、後段Gを同一にする。違いはrow contextだけ。
- 既存`L24-160+G`は履歴上の参考値。T1-256との差をT1の因果効果と呼ばない。
- もし計算量を抑えるため160で始めるなら、対照もT1も160に固定する。ただしrow contextの切詰め率を先に記録する。
- G4は行対応値つきで予測前に凍結し、先生2人の独立ラベル→裁定→Codex見直しを維持する。固定後に結果を見て表を追加しない。
- 主指標は従来の正答、unknown、重大、その他誤り、公開元単位区間、seed再発性。さらに型別、行文脈あり/除外、切詰め別を診断に残す。
- NはT1の主判定に混ぜない。必要なら同じ保存予測への後処理診断として、変更全列と採点外の新規断定を報告するが、T1の採否とは分離する。

## 外部研究・データの読み

DODUOの表全体文脈という方向は根拠になる。一方、「外のデータは使えるものが無い」は全世界についての確定事実ではなく、調査した候補が現在の権利・金ラベル方針では未承認という範囲に留める。SOTABはWDC Schema.org由来の別taxonomyで、現在の16種へ自動変換して学習に入れない判断に賛成する。外部データを使わず金教材を使うことと、DODUOのApache-2.0コード／考え方を参考にすることは分けて記録する。
