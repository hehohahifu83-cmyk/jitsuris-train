## 2. 公開元の割り当て（評価と学習を、人の選択ではなく規則で分ける）
目的：評価セットと学習データが同じ公開元（自治体・省庁・ベンダー）から取られて、見かけの成績が上がることを防ぐ。
```python
import hashlib
def pool(publisher_id: str) -> str:
    # publisher_id：公開元の正規化名（NFKC・小文字・空白除去）。CKAN があれば organization.name。ベンダー仕様は "vendor:<名前>"
    h = int(hashlib.sha256(f"jitsuris-alloc-v1|{publisher_id}".encode("utf-8")).hexdigest()[:8], 16) % 100
    return "eval2" if h < 15 else "eval3" if h < 30 else "train"
```
- 新しく見つけた公開元は、**中身を見る前に** `pool()` で割り当て、`independent_eval/allocation.json`（公開元 ID・プール・日付）に追記する。後から付け替えない。
- `eval2` `eval3` の公開元は、学習データに入れない。`train` の公開元は、評価セットに入れない。
- 既存の学習の系統（egov・egov_biz・egov_biz2・jp・jp2・datagov_uk・datagov_uk2・canada・canada2・ireland・australia・gittables・direct）は `train` に固定。主セットの 4 出典（横浜・神戸・札幌・NYC）は `main`（以後、学習に入れない）。
- 同じ組織の別名・別ポータルは同じ公開元に正規化する（表は `allocation.json` の `aliases`）。判断に迷う公開元は、割り当てを待たずに `eval` 側として扱う（安全側）。

## 3. セットの規格
### 封印セット #2・#3（それぞれ）
- 列 600 以上（目標 700）、表 60 以上、公開元 12 以上、データセット 40 以上、1 表あたり 10 列まで、1 公開元あたり全体の 12% まで。
- 日本語を含む列 55% 以上、英語など他言語 25% 以上。見出しが学習にもある列は 20% 以下（凍結前に、見出しだけで数えられる）。同じ見出し集合の表は 1 セット 2 表まで。
- 種類の下限：**列名の語による粗い推定**（`independent_eval/rough_class.py`、ラベルではない・記録に残さない・量の配分にだけ使う）で、金額・数量・日付・番号・会社名・区分・文章・住所・その他が各 40 列以上、率・勘定科目が各 25 列以上になるように選ぶ。人名・電話・メール・商品・税区分は公開データでは足りないので PD-1 に任せる。
- 出典とライセンス：個別に確認した、再配布できる条件だけ（CC0・CC BY・政府標準利用規約 2.0・PDL 1.0・OGL など）。NC・SA・条件不明・有償表示は除外。主セットの `allowlist.json` と同じ審査（プライバシー：氏名・住所・電話・メール・URL・生徒・福祉・医療の除外）。
- 取り出すのは、選んだ列の先頭 5 データ行・同じ表の列名・単位列の値だけ。元の CSV を保存しない。`provenance.json`・`ATTRIBUTION.md`・セットの SHA-256 を残す。
- 学習側との重なり：URL の完全一致 0（real_corpus*.jsonl と real_labels*.jsonl の全部と比べる）、公開元の一致 0。
- 凍結したら、値を開かない（自動のプライバシー検査と SHA-256 だけ）。**値を見てよいのは、手順 4 の「ラベル付け」の段階から**。

### PD-1（製品領域・仕様由来）
- 公開元は `vendor:<名前>`。`pool()` で `train` 以外（`eval2`・`eval3`）に割り当てたベンダーの形式だけを PD-1 に、`train` のものは仕様由来の教材（DATA_COLLECTION_PROTOCOL.md 第 4 章）に使う。形式が 12 に足りなければ、ベンダーの候補を増やして規則どおりに割り当て直す（割り当てた後の付け替えはしない）。
- 形式 12 以上（会計ソフトの仕訳・取引の入出力、請求書、売上・POS・EC の注文、銀行・カードの明細、給与、在庫など）、800 列以上、15 種類のうち other 以外は各 40 列以上（other は 20 列以上）、1 形式から全体の 10% まで。
- 見出しは公式ヘルプ・仕様書の列名（URL・取得日・利用条件を記録。**列名と、勘定科目や税区分のような公式の語彙の事実だけを記録し、説明文や見本ファイルは転載しない**）。
- 値は `pd_gen.py` で生成する：`gen.py` を import しない、語彙を `gen.py` から写さない（`pd_gen.py` の先頭に由来を書く）、乱数の種と生成コードのコミット SHA を固定。表記ゆれは、そのベンダーの出力例に載っている書式だけ（全半角・桁区切り・和暦・△・欠損の印・末尾の空白は仕様の範囲で）。
- ラベルは仕様から決まる列だけを入れる（仕様が型を決められない列は入れない）。構成時に確定し、Claude が 10% を無作為に抜いて仕様の読み違いを確かめる。
- 使い方は封印セットと同じ（固定 → 予測 → 採点）。誤りの分析をしたら使い切りとし、次は別のベンダー割り当てで PD-2 を作る。

## 4. 手順（順番を変えない）
| 段 | やること | 誰が | 確かめること |
|---|---|---|---|
| 0 | セットを作って**凍結**（SHA-256 を記録）。値は誰も開かない | ChatGPT | `provenance` に `labels_written=false`・`values_viewed=false` |
| 1 | **候補を固定**して**事前登録**：重み（manifest の SHA-256）、入力形式、ガードの版、しきい値、LABEL_GUIDE の版、指標、判定規則を `independent_eval/PREREG_<セット>.md` に書いてコミット。コミット SHA を連絡箱に書く | ChatGPT（Claude が検収） | 予測より前のコミットか |
| 2 | **予測**（ラベルなし）：`evaluate_independent.py predict`。Actions の CPU で。台帳に各（セット, 重み）1 回だけ。予測ファイル（値なし）をコミット | ChatGPT | 台帳。値・ラベルが公開リポジトリにない |

- 主セット #1 は段 0・3（Claude の分）が済み。残り：ChatGPT のラベル固定 → 段 4 → 段 1（事前登録）→ 段 2 → 段 5 → 段 6。**段 1 は段 2 より前**。

## 5. 指標と報告の形（`bench/independent_eval_<セット>.md`）
- **主指標**：未知の見出しの列の OK 率（ガード後。OK＝正解、または正解が other で不明）。
- 副指標：全体の OK 率、macro-F1（正解側 5 列以上の種類）、重大な取り違え（件数・率）、誤断定（不明でない誤り）、不明の率、種類別の適合率・再現率、**正解が unknown の列への言い切り率**（採点の外だが、決められない列に言い切る癖を見る。`score` の manifest の `n_unknown_labeled`・`unknown_asserted`・`unknown_asserted_ids` に出る。S の列は数えない）、**確率の下限を動かしたときのカバー率と精度**（重大 5 種類は精度 99% で何割の列を答えられるか）。
- 区間：**表単位のブートストラップ**（表を復元抽出、10,000 回）の 95% 区間。候補どうしの差は対応のある差の区間。重大 0 件は「95% 上限は 3／重大 5 種類の正解列の数」を併記。
- 層別（すべて同じ表で）：見出し既知／未知、出典別、言語別、ラベルを付けた人別（Claude・ChatGPT・裁定後）、**先生の一致した列／食い違った列**、種類別。重大 5 種類の 5×5 の混同表。
- 末尾に再現のコマンド、各ファイルの SHA-256、ガードと LABEL_GUIDE の版、事前登録のコミット SHA。
- 結果は「実装・検査・実接続・実績」を分けて書く。

## 6. 判定規則（事前登録に写す）
- **主セット #1（土台の比較）**：mmBERT-small を採るのは、(1) 未知見出しの OK 率の平均が E5-base より 2.0 ポイント以上高く、(2) 重大の平均が E5-base 以下、(3) 差の 90% 区間の下限が 0 を超える、をすべて満たすときだけ。そうでなければ E5-base を残す。診断では E5-base が上なので、E5-base が残る見込み。
- **封印セット #2（学習候補の判定）**：候補（最大 4）と基準線（E5-base の版 31 の重み）を同じ #2 で測る。候補が採用候補になるのは、基準線との差が +2.0 ポイント以上、差の 90% 区間の下限が 0 超、重大が基準線以下、を満たすとき。複数が通れば、事前に書いた順（学習の単純さ）で最初のもの。通らなければ基準線を残す。
- **封印セット #3・PD-1（合格判定）**：IMPROVEMENT_PLAN.md の G1〜G6。不合格なら、そのセットを使い切りとして、原因分析のあと新しい #4・PD-2 を作る。
- ラベルの人で結論が割れたら（Claude のラベルで勝ち、ChatGPT のラベルで負け、など）、**採用しない**（裁定後のラベルでも同じ結論のときだけ採る）。
- 結果を見てから候補を足す・規則を変えることはしない。足したくなったら次のセットで。

## 9. 先生の初回ラベルとモデルの比較（S14。「ChatGPT・Claude と同等以上」の測り方）
外部の API を使わずにできる比較：
- 同じ列・同じ入力（見出し・先頭 5 値・同じ表の列名・単位列）を先生に見せて付けてもらった**初回ラベル**を、裁定後のラベルに対して採点する。モデルも同じ列で採点する。
- 注意：裁定後のラベルは先生の初回ラベルから作るので、先生の点は**甘く出る**（食い違い率の半分ほど）。モデルが先生の甘い点に並べば、「同等以上」の強い証拠になる。
- 先生の一致した列だけ・食い違った列だけでも、モデルの OK 率を出す（一致した列＝ラベルが確かな列でのモデルの本当の力）。
- 先生とモデルの誤りの重なり：先生は正しくモデルが誤り（学べるはずの列）／両方誤り（ラベルの曖昧さか本当に難しい列）。前者を次の教材の候補にする（封印セットの列は教材にしない。学習側の候補で同じ分析をする）。
