# 教材監査手順（Claude / ChatGPT）

## 目的と境界

対象は表の列種別判定の教材だけ。判断基準はリポジトリの `LABEL_GUIDE.md`。モデルの性能を上げるための監査であり、教材を増やすこと自体を目標にしない。候補投入は直ちに学習へ反映されない。監査済み教材だけを `reviewed_replay.jsonl` に昇格する。

未見評価データを守る。blind_set*、セット3・5・7、評価・テストデータは絶対に開かない・候補にしない・学習に入れない。顧客データ、個人情報、秘密情報も使わない。

## 共同監査（Claude と ChatGPT の両方が利用できる場合）

1. 候補は `materials/inbox/claude_candidates.jsonl` または `codex_candidates.jsonl` に、正解ラベルなしで追加する。各候補には安定したID、列名、値、兄弟列などの文脈、単位、出典URL、データセット/表名、ライセンス、プライバシー確認を付ける。
2. 2人は互いの判定を見ずに、同じ LABEL_GUIDE の版を使って独立にラベルを付ける。候補が少ない場合も、先に相手の判定を見ない。
3. 各自、ID・ラベル・確信度（high/medium/low）・根拠・除外理由を別々のレビュー記録に書く。
4. ラベルと「採用/除外」の判断が一致し、両者が high または medium とした行だけ採用候補にする。2人が不一致、片方が low、ラベル定義に該当しない、出典/ライセンス/プライバシーが未確認なら保留または除外する。
5. 不一致は列名だけで決めず、値・単位・同じ表の列・出典を根拠に照合する。解決できなければ無理に裁定せず除外する。合意した新しい一般ルールは LABEL_GUIDE の改訂提案に記録し、版更新は別途レビューする。
6. 採用した行だけ `reviewed_replay.jsonl` に、両者の名前・独立判定・根拠・確信度・合意状態を残して追記する。元の候補ファイルとレビュー記録は保持し、履歴を消さない。

## 単独監査（片方しか利用できない場合）

1. 手順1の候補要件、未見セット禁止、出典・ライセンス・プライバシー要件は同じ。
2. LABEL_GUIDE を行ごとに適用し、列名・値・文脈・単位・表の出典のどの根拠がラベルを支えるか記録する。モデル予測や候補作成者の推測は正解の根拠にしない。
3. high 確信で、根拠が相互に矛盾せず、既存ラベルの定義に明確に一致する行だけ「単独監査」として採用候補にする。medium/low、曖昧な値、文脈不足、ラベル境界の揺れ、単位と列名の矛盾は保留または除外する。
4. 監査者名、利用可能だった監査者数（1）、監査日、確信度、根拠、除外理由を必ず記録する。二者一致と同等の確度だとは主張しない。
5. Claude が戻ったら、単独監査で採用した行も可能な範囲で独立再監査する。不一致が出た行は学習から除くか、根拠を残して再裁定する。

## 採用・学習・効果確認

- 監査状態が明示された行だけを学習用ファイルへ移す。候補 inbox のファイルを直接学習入力にしない。
- 採用前に既存教材との重複・矛盾、ラベル集合、JSONL形式、禁止データパスを検査する。
- 学習に入れた事実はログと SHA-256 付き receipt で確認する。receipt は学習過程への投入を示すだけで、モデルが意味を学んだ証明にはならない。
- 事前に決めた固定5セットの正解率・誤り・重大誤り・unknown・時間・最大GPUメモリを記録する。盲検指定のセットには触れない。
- 乱数seedを合わせて比較し、1.5ポイント未満の差は差なしとして扱う。単独監査教材による改善と二者監査教材による改善は別に記録する。
- 誤りが増える、重大誤りが増える、または評価の再現ができない場合は、追加教材を採用せず原因調査を優先する。

## Claude への作業メモ

利用制限が解除されたら、この手順と LABEL_GUIDE を先に読み、inbox の未監査候補を確認する。まず独立ラベルの記録を作り、ChatGPT の判定を見る前に確定する。追加する候補は Claude 用 inbox に追記し、既存の候補や監査済み教材を上書きしない。
