# LABEL_GUIDE v1.9 境界規則の提案

調査日：2026-10-25  
対象根拠：現行 `LABEL_GUIDE.md` v1.9 と教材庫 b001〜b014。固定試験、封印セット、モデル予測、Claude のラベルは参照していない。**提案のみ**であり、ガイド本文は変更していない。採否と版上げは Claude が決める。

## 先に置く共通の判定順

文字列の見た目や数値形式だけで決めず、「その列が何を表すか」を示す根拠を優先する。

1. 見出しにある単位・明示語（円、%、時刻、コード、部署など）。
2. 表題・列の説明・分類項目が示す意味。
3. 同じ表の他列との関係（単位列、期間列、名称列、対になるコード/説明列）。
4. 値が示す形式・反復のしかた。

この順でも複数解釈が残る場合は、ラベルを推測で確定せず `unknown` または `S` とする。特に `value`・`number`・`name` だけでは決めない。

## 1. quantity ↔ id

**提案規則：** quantity は数えられる量・測定単位・期間の長さを表す。id は物や行を識別・参照・並べ替えるためのキーであり、連番でも量ではない。連続性や整数であることは決め手にしない。

- 例：b001 の年齢階級見出し（`15歳以上` など）は、年齢階級ごとの人数を表す列として quantity。隣の `産業（大分類）` は値が産業区分なので category。
- 例：`施設件数`・`容量（L）`・`勤務年数` は quantity。ガイド v1.9 の「件数・年齢・経過年数・時間数・kg は quantity」と同じ。
- 反例：`施設番号`・`受付コード`・`No.`・`index` は id。値が 1, 2, 3 と連番でも quantity にはしない。
- 境界：`number` だけで件数か番号か不明なら unknown/S。日時形式らしい番号やゼロ埋めだけでも id に決めない。

## 2. amount ↔ rate

**提案規則：** 金銭の単位・通貨・金銭語（価格、税額、費用、収入等）が明示されるなら amount。割合・分母・比較期間を示す単位（%、per 100、前年比等）が明示されるなら rate。値が小数か 0〜1 かだけでは決めない。

- 例：`税額（円）` は amount、`税率（%）` は rate。両方が同じ表にあってもラベルを混同しない。
- 例：ガイド v1.9 の統計表 `VALUE` は、対応する `UNIT` が Euro/€ なら amount、%/per 100 なら rate、Number/Sq Metres なら quantity。
- 反例：測定値（例：気温）や得点は amount ではない。ガイドでは測定値・点数は other。
- 境界：単位・表題・隣接列のどれにも根拠がなく、見出しが `value` のような汎用名なら unknown/S。金銭の「料金」と割合の「率」を言葉の一部だけで自動判定しない。

## 3. date ↔ id

**提案規則：** 暦上の時点・日付・時刻・年月・年度を表す列は date。対象を識別する固定キー・連番・コードは id。日付として妥当な数字列であることだけでは date にしない。

- 例：`年度` が会計年度の時点を指す場合は date。ガイド v1.9 の `2021`・`2016年度` は date。
- 反例：`登録番号`・`整理番号`・`C02345V03131`・`N92000002` は id。年月に似たコードでも定義が識別子なら id。
- 反例：`経過年数`・`勤続年数` は quantity（date ではない）。
- 境界：`20241025` のような値は、見出し/説明が日付を示す場合だけ date。レコードキーか日付か見分ける説明がないときは unknown/S。

## 4. text ↔ category ↔ other

**提案規則：** 値が自由な文章か、限られた選択肢か、測定/統計値かを分ける。

- category：決まった分類語・状態・有無・曜日・選択肢コード。例：b001 の `産業（大分類）` のように、林業・教育等の区分を示す見出し。
- text：備考・説明・摘要など、値ごとに内容が変わる自由記述。短い語であっても記入者ごとの文章なら text。
- other：気温・濃度・座標・平均・標準偏差・得点など、ラベル定義にある測定値/統計値。数値であることだけで quantity や amount にしない。
- 反例：有/無、○/×、0/1 の二値フラグは category。値が文章でなく短いからといって text にしない。
- 反例：`status` の定型状態は category、`description` の自由な文章は text、`mean temperature` は other。
- 境界：`type`・`description`・`value` だけで値の意味が分からない場合、値の一部を推測して断定しない。選択肢か自由記述か、測定値かを確定できなければ unknown/S。

## 5. org ↔ address ↔ account

**提案規則：** 組織として活動する主体、場所、組織内の会計/部門区分を分け、列名だけでなく値の役割を見る。

- org：会社・役所・学校・病院・駅など、運営/発注/支払の主体としての名称。
- address：住所、自治体名、地点、建物・土地・公園等の場所としての名称。
- account：勘定科目、費目、基金、部門、部署、課、cost centre など、組織内の管理/会計区分。
- 例：`Health Department` が独立した役所・発注者なら org、`Department` が支出を割り当てる課なら account。ガイド v1.9 の `Department`・`Directorate` は値が実際の役所名か部署名かで判定する。
- 例：病院運営者の名前は org、病院の所在地や公園名は address、`General Fund` や `Cost Centre` は account。
- ポルトガル語の候補では `órgão/entidade` が実施主体なら org、`município/endereço` が場所なら address、`unidade gestora/centro de custo/rubrica` が予算単位なら account。
- 境界：`name`・`department`・`facility` だけで主体/場所/部署の違いが決められない場合は unknown/S。図書館などは運営組織か建物かを表題・説明で確認する。
